`llm_d_async_async_inference_latency_time_millis` carries the request's trace as an exemplar (`trace_id`, plus `span_id` of the `process-request` span) when the trace is sampled, and the metrics endpoint serves OpenMetrics to scrapers that ask for it, so a point on a latency panel links to its trace. Scrapers that don't ask get the classic format. The chart's dashboard gets an inference latency panel that shows the exemplars. On Prometheus 2.x, OpenMetrics scrapes store whole-number bucket bounds as `le="10.0"` rather than `le="10"`, so a query that matches `le="0"` on `llm_d_async_async_deadline_proximity_millis` needs `le="0.0"`.
