Request transforms can implement the optional `transform.ContextTransform` interface to receive the request's context (deadline and shutdown) and dispatch URL. A transform error whose chain carries a `RATE_LIMIT` or `SERVER_ERROR` category is now retried with backoff instead of failing the request. A transform cut off by the request deadline reports `DEADLINE_EXCEEDED`, and one interrupted by shutdown is re-enqueued. `transform.Chain.Apply` is deprecated in favor of `ApplyContext`.

Adds the `s3_multipart` request transform for vLLM's `/v1/audio/transcriptions` and `/v1/audio/translations`, which accept only multipart uploads. It reads the JSON `file` field, an `s3://bucket/key` reference from an S3-compatible store (AWS S3, SeaweedFS, MinIO) or a base64 `data:` URL, and sends it as the `file` part with the remaining fields as form fields. It is configured with `endpoint`, `region`, `usePathStyle`, a required `allowedBuckets` list and `maxFileBytes` (default 25 MiB), and takes credentials from the standard AWS environment variables. Storage throttling, 5xx, timeouts and connection errors are retried; missing objects, denied access and disallowed buckets fail the request.
