Adds the `s3_multipart` request transform for vLLM's `/v1/audio/transcriptions` and `/v1/audio/translations`, which accept only multipart uploads. It reads the JSON `file` field, an `s3://bucket/key` reference from an S3-compatible store (AWS S3, SeaweedFS, MinIO) or a base64 `data:` URL, and streams it into the `file` part with the remaining fields as form fields. A body without `file` passes on to the next transform. It is configured with `endpoint`, `region`, `usePathStyle`, a required `allowedBuckets` list and `maxFileBytes` (default 25 MiB), and takes credentials from the standard AWS environment variables. Storage throttling, 5xx, timeouts and connection errors are retried; missing objects, denied access, disallowed buckets and any failure to get credentials fail the request (`AWS_EC2_METADATA_DISABLED=true` off EC2 skips the metadata-service lookup first).

`s3_multipart` also handles vllm-omni's `/v1/images/edits`. It maps OpenAI-style `images[].image_url` to `url` form fields, presigning `s3://` references, so vllm-omni fetches the images itself without storage credentials. `data:image/` URLs pass through, and other URLs are rejected. Each presigned URL is valid until the dispatch attempt's deadline (at most 7 days, and ending before the signing credentials' reported expiry), and every retry signs a fresh one.
